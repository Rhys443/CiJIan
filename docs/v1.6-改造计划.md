## 一、玻璃：已确认的参数

用户在范例 `cijian-v18-demo.html` 里拉定的数值：

| 参数 | 值 | 含义 |
|---|---|---|
| 液态程度 | **0.08** | 剖面在「四分之一圆」与「smootherstep」之间插值。0.08 基本还是圆角剖面 |
| 鼓起范围 | **30%** | 隆起范围占面板短边的比例 |
| 鼓起高度 | **17** | 表面最高点的高度（像素量级） |
| 边缘厚度 | **0.07** | 贴边一圈的轻微压暗 |

**读法：不要大变形。** 只要边缘一圈**轻微、窄、柔**的隆起 —— 观感上几乎还是平的，
但边界不是「折」出来的。

### 已经查清的三条「棱」的来源（都要去掉）

「像台状的四棱台，有分割线」是用户的准确描述。四棱台 = 平顶 + 四圈斜面，
交界处有棱。按这个思路逐条排查：

| # | 来源 | 状态 |
|---|---|---|
| 1 | 剖面在边缘**切线垂直**（四分之一圆 `√(1−(1−t)²)` 在 t=0 处导数无穷）→ 表面以 90° 撞上边界 | 改 smootherstep，两端一阶二阶导都为 0 |
| 2 | **平顶与弧面的交界**本身又是一道折痕 | 鼓起范围设满，整块面板都在隆起，没有平顶 |
| 3 | **边缘亮度在边界上的台阶**：`mix(1-edge, 1, smoothstep(0,0.55,t2))` 在 t2=0 处等于 `1-edge`，而面板外没有这个系数 → 边界两侧差 `edge` 的亮度 | 改成**贴边为 0 的鼓包**：`smoothstep(0,0.22,t2) * (1-smoothstep(0.22,0.70,t2))` |
| 4 | **一圈平行于边缘的暗带**（边缘厚度）—— 形状上无折角，但明暗上就是一条环绕的线 | 参数压到 0.07；再往下就是 0 |

**关键认知：前几轮我一直在调形状（倒角宽度、球面凸度、切线角度），但用户看的那条线
有三条来源其实是「明暗」而不是「形状」。形状再顺滑也消不掉明暗上的台阶。**

### 参照物

- 范例 `cijian-v18-demo.html`（左半固定是旧参数当对照，右半跟着滑杆）
- 底图用 base64 内联。**注意：`file://` 页面里的本地图片在 Chromium 里算跨域，
  WebGL 上传纹理会抛 SecurityError，纹理留空 → 背景全黑。而且异常发生在

  已经踩过一次，范例上是第二次。**

## 二、主题色：逻辑要理顺（用户原话）

> 「我不需要 3 个板块来负责同一个页面的主题色问题，这非常浪费我们的板块资源。」

现在 **周期主题 / 外观 / 背景** 三个板块指向的都是「整个界面长什么样」。合并成 **1 个板块 + 3 行**：

| 行 | 内容 |
|---|---|
| 强调色 | 红 橙 黄 绿 青 蓝 紫 + **自动**（跟着底图） |
| 明暗 | 浅色 / 深色 / 空间 |
| 底图 | 移除 / 黄昏 / 林间 / 夜色 / 上传… |

**三者的关系（一条链）：**
1. **底图**决定背景是什么，并**自带**一个推荐强调色（选林间自动配绿）
2. **强调色**可以手动覆盖底图的推荐值
3. **明暗**只决定玻璃厚薄与取色档位，**不再决定颜色**

**周期主题不再改颜色。** 它本来就是「这一轮练什么」（动起来/燃点什么/连上谁），
是**内容**不是**外观**，只影响抽卡抽到哪一池任务。

### 已经踩过的坑（务必保留结论）

- **场景色被硬编码盖掉**：`[data-scene]` 是 (0,1,0)，而旧的
  `[data-bg="photo"][data-theme="move"]{--theme-text:#ffb184}` 是 (0,2,0) → 场景色失效，
  面板变绿了但文字还是橙的。
- **修法：每个主题/场景一次给三个值**，模式只负责挑：
  `--theme`（填充）/ `--theme-deep`（亮底文字）/ `--theme-hi`（暗底文字）。
  **不许再有任何具体颜色散落在外面。**
- **自动色要压饱和度**：照片的平均色相通常很脏（灰绿、土黄），
  直接用会得到一个说不清是什么的颜色。压到 40% 左右才像「这套图的气质」。
- **换色相后感知亮度会变**：黄和青比红蓝亮得多，同一个明度值压上去，
  黄按钮上的白字根本看不清。所以每个色相配的是**完整一组**，不是转一下色相。

用户看不出空间与深色有多大区别。**已按此实施**：空间模式的强调色改为中性灰白

## 四、文字取色（已确认的规则）

> **只有极光（没底图）用棕黑字；只要设了底图，一律白字。**

- 极光：`--text` = ink 系列（`#2a2320` 带一点棕的灰黑）
- 底图：白字 + 暗玻璃

**中间踩过的坑：** 我把「暖白用棕黑字」误读成对底图模式也成立，
做过一版「浅色 + 底图 = 暖白玻璃 + 棕黑字」，结果照片被实心暖白盖住、玻璃全丢。已回退。

### 尚未实现：不在板块上的文字自适应取色

**用户要求：** 所有不在板块上的文字，要检测它**下方周围那一圈**是深是浅 ——
深色用白字，浅色用棕黑字。

**范例 v1.5 第 2 节已经做出可运行的实现**，做法：
把底图缩到约 48px 宽当亮度图，文字定位时采样下方 **3×3 格**的平均亮度
（比单点稳，不会因为文字压在一根细线上就整行翻色），低于阈值给白字、
高于给棕黑字，120ms 过渡。

**它同时是「去掉那层灰」的前提**：以前是「把背景压暗好让白字看得见」，
代价是整屏发灰；改成「背景保持原样，文字自己换色」才回得到「白净透亮」。

### 第 2 项：那条灰带到底是什么（结论）

**是 `.rail-edge::after`。** 它是 surfaces.css 里那条「侧栏与内容区之间的 10px 模糊带」，
本意用 `right: -10px; width: 10px` 挂在侧栏**右缘**。

但 glass.css 里 `.is-glass::after { inset: 0 }` 与它**同为 (0,1,1)**，
而 glass.css 排在 surfaces.css 之后 → 层叠上 inset 赢，`left` 被钉成 0；
`width: 10px` 又没有被任何规则覆盖。
**左右同时有值 + 又给了宽度 = 超定**，按 LTR 规则 `right` 被丢弃 ——
整条带子从右缘跑到**左缘**：10px 宽、满高、方角（它自己没写圆角），
正是「窗口左边那条怎么都去不掉的灰带，顶部是方的」。
它带 `backdrop-filter: blur(6px)`，所以底图亮它就是亮的、底图暗它就是暗的，
看起来像"一层灰"。

**修法**：`surfaces.css` 里把选择器写成 `.rail.rail-edge::after`（抬到 (0,2,1)），
并显式补 `left: auto`（这条规则自己从没声明过 left，不写的话 left:0 会从
`.is-glass::after` 漏进来）。提高优先级是**结构性**的修法：
以后谁再接样式表也不会把它重新挤到左缘。

**定位手法（可复用）**：`dev/shot.js` 这轮加了四个开关 ——
`--outline`（逐层彩色描边）、`--geom`（打印各层真实盒子 + 送进着色器的面板矩形）、
`--hide=`（逐层关掉，消去法）、`--css="规则"`（注入任意 CSS 做假设验证）、
`--still`（**停下极光漂移，做像素级对照必须加**）、`--early=MS`（开屏后立刻拍）。

两条方法论教训：
1. **极光每跑一次都在漂移**，跨进程比同一坐标的像素比的是两团不同的光；
2. **不要并发跑两个 shot 实例** —— 抓屏抓的是整个屏幕，会拍到另一个实例的窗口。

### 第 1 项：玻璃（已落地的参数与实现）

`optics.js` 的 `GLASS`：

| 参数 | 值 | 说明 |
|---|---|---|
| `liquid` | **1.0** | 剖面在四分之一圆与 smootherstep 之间插值 |
| `spanRatio` | 0.30 | 鼓起范围 = 短边 30% |
| `height` | 17 | 鼓起高度（css px） |
| `edgeShade` | 0.07 | 边缘厚度（贴边为 0 的鼓包） |

**`liquid` 取 1.0，不是文档里记的 0.08 —— 因为 0.08 在数学上做不到"去掉直角"**：
剖面是 `mix(brick, smootherstep, liquid)`，而 `brick = sqrt(1-(1-u)^2)`
在 u=0（正好在轮廓上）的导数**无穷**。只要 liquid < 1 这一项就还在，
表面照样以 90° 撞上边界 —— 那正是用户说的直角。
所以按「结构性修改」那一条取纯 smootherstep：两端一阶二阶导都为 0。

另外两处一起改了：
- 边缘亮度从 `mix(1-edge, 1, smoothstep(0.55,1,t))` 改成
  **贴边为 0 的鼓包** `smoothstep(0,0.22,u)*(1-smoothstep(0.22,0.70,u))`
  —— 前者在轮廓上等于 `1-edge`，面板外没这个系数，边界两侧差 edge 的亮度；
- 表面倾角 `tanPhi = (height/span) * profileSlope(u)`，
  **不再乘折射厚度** —— 形状与厚度分开，厚度只负责"同样的倾角能掰弯多少背景"。

### 另外两个「发灰」的根（都已修）

1. **极光模式下整屏被压暗 30%**（`bg.overlay` 默认 0.30，`clearBackground` 也是 0.30）：
   浅色下画布上画出来的是 `#a1998d`，而 CSS 令牌 `--bg` 是 `#e6dbca` —— 一层脏灰。
   **照片那条路径早就改成按底图亮度自适应了，极光这条一直漏着。**
   现在按外观分档：浅色 0.06 / 暗房 0.30 / 空间 0.34。
   （顺带修了 `setOverlay()`：渲染循环每帧把 overlay 往 overlayTarget 插值，
   只写 overlay 的话下一帧就被拉回去 —— 这就是截图工具 `--overlay0` 一直是空操作的原因。）
2. **DOM 面板上那层白纱太厚**：`[data-optics="webgl"] .card` 等原来是
   `color-mix(--surface 72%)`（约 0.60 的白），等于"底图上面盖了一张半透明白纸"，
   折射只剩一成可见度。用户原话：**不能把液态玻璃单纯叠加在底图上，
   要把底图融合进玻璃的扭曲效果里**。现在收到 26%（侧栏 30%），
   照片底图单独保留 62%（白字要靠背衬）。

### 第 3 项：15 格相纸首帧颜色错位（没抓到现场）

`--early=900` 的开屏首帧与稳定后**逐格一致**，没有复现。
按最可能的成因做了防御性修复：照片被圆角容器裁切时，
首帧合成层可能绕过 `border-radius` 的裁切，于是照片溢出到格子方角之外
（看上去就是"格子外面那一圈底色跟着照片主色走了"），重渲染一次就好了 ——
这与用户描述的**症状与"重渲染即恢复"都吻合**。
修法是给图片自己补上 `border-radius: inherit` + 给裁切容器加 `isolation`。

### 第 5 项：设置合并（已做）

- 强调色 / 明暗 / 底图 合并成**一个「外观」板块**（外加"减少动态效果"一行）
- 强调色的唯一来源是 `documentElement.dataset.accent`（tokens.css 里七组完整色组）
- **周期主题不再改颜色**，改名「这一轮练什么」，只决定抽卡池与极光色调
- `data-scene` 那一套 CSS 整个撤掉（它正是"面板绿了、标题还是橙的"的来源）
- 自动色：预设自带色相（黄昏→橙/林间→绿/夜色→蓝）；
  用户照片取**均值色相**再落到最近锚点 —— 只取色相，
  饱和度明度用调好的那七组（等于把饱和度压到四成），
  近乎灰的照片返回 null 交给兜底

### 两条血的教训

1. **GLSL 注释里绝对不能出现反引号。** 着色器整体在 JS 模板字符串里，
   反引号会提前把模板字符串截断 → 整段脚本语法错误 → 界面静默退回 CSS 版本。
   **已经踩过两次。**改完先数一遍文件里的反引号总数（应为偶数）。
2. **`capturePage()` 在透明窗口 + 全屏 WebGL 画布下会永久挂起**，用 `desktopCapturer` 抓屏后裁窗口矩形。
