# 此间 · 设计规范

> 基准：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)
> 落地文件：[`renderer/css/tokens.css`](../renderer/css/tokens.css)

---

## 一、为什么选 Apple HIG 作为基准

「此间」的产品内核是**仪式感**：慢、安静、私密、有实体感。
Apple HIG 的三条原则恰好对应这三件事：

| HIG 原则 | 官方表述 | 在本项目里的落地 |
|---|---|---|
| **Clarity（清晰）** | 文字在任意尺寸下都清晰可读，图标精准，留白得当，以视觉层级传达重要性 | 字号/字重/颜色三级 Label 承担层级；不用边框和分割线堆砌结构 |
| **Deference（退让）** | 界面帮助用户理解内容并与之交互，但绝不与内容竞争 | 界面材料是暖纸与半透明材质，**相纸永远是屏幕上最亮的东西**；全应用只在模态遮罩用一次 `backdrop-filter` |
| **Depth（纵深）** | 用层次与真实的动效传达层级、赋予生命力，帮助理解 | 分层阴影表达高度；相纸会「吐出来」「显影」；页面切换带纵深位移动画 |

## 二、颜色

### 语义色（Semantic Colors）

HIG 要求用**语义命名**而不是「蓝色/红色」来定义颜色，这样亮暗模式与主题切换只改一处。

| 令牌 | 亮色 | 暗色（暗房） | 用途 |
|---|---|---|---|
| `--bg` | `#f6efe6` | `#171310` | 窗口底色，暖纸/暗房 |
| `--surface` | `rgba(255,253,250,.86)` | `rgba(36,30,26,.74)` | 卡片、面板（半透明材料） |
| `--surface-solid` | `#fffdfa` | `#241e1a` | 需要完全不透明的表面 |
| `--surface-sunken` | `rgba(228,214,196,.4)` | `rgba(0,0,0,.28)` | 凹陷区：轨道、分段控件 |
| `--separator` | `rgba(58,49,44,.1)` | `rgba(246,239,230,.1)` | 分隔线（比边框更轻） |
| `--text` | `#2a2320` | `#f2e9dd` | Label（主文字） |
| `--text-soft` | `#6b5d53` | `#cec1b3` | Secondary Label |
| `--text-mute` | `#8a7c71` | `#a89b8e` | Tertiary Label |
| `--text-faint` | `#a99c91` | `#837568` | Quaternary Label |
| `--theme` | `#cf6438` | 同 | 主色（三个主题各有一套） |

**关键取舍**

1. **不用纯黑，也不用纯白。** 文字是暖褐墨色，暗色模式的文字是暖纸白 `#f2e9dd` 而不是 `#fff` ——
   纯白在深色界面上会产生泛光（halation），这正是「深色 UI 看起来像通用仪表盘」的常见根因。
2. **阴影色统一为暖棕 `rgba(74,55,38,α)`。** 纯黑阴影铺在暖奶油底色上会显灰、显脏。
3. **对比度**：正文 `#2a2320` on `#f6efe6` 约 13:1（AAA）；次要文字 ≥ 4.3:1（AA）。

### 主题皮肤

三套任务池各自有一套主题色，只覆盖 `--theme*` 与两个极光色，其余全部继承：

| 主题 | 主色 | 情绪 |
|---|---|---|
| 🏃 动起来 | `#cf6438` 陶土橘 | 身体、温热、行动 |
| 🎨 造点什么 | `#b0793c` 赭黄 | 手作、纸与黏土 |
| 🤝 连上谁 | `#7d6a8f` 藕紫 | 关系、柔软、夜谈 |

## 三、字体与排版

### 字体栈

```css
--font-sans: -apple-system, BlinkMacSystemFont, "SF Pro Text", "SF Pro Display",
             "PingFang SC", "HarmonyOS Sans SC", "MiSans", ... ;
--font-serif: "Source Han Serif SC", "Noto Serif SC", "Songti SC", "STSong", ... ;
--font-hand:  "Xingkai SC", "STXingkai", "LXGW WenKai", "Kaiti SC", "STKaiti", ... ;
--font-num:   -apple-system, "SF Pro Display", "Optima", "Palatino Linotype", ... ;
```

- **Latin 用系统 SF Pro 字体栈**，中文落到苹方（macOS 原生 / Windows 上回退到微软雅黑）
- **宋体**承担标题：给「第 7 天」这种带编号的信息一种**被记录**的正式语气
- **楷体**承担手写感想：让背面那几行字读起来像真的用笔写的
- 三套字体均为系统字体，**不需要内嵌任何字体文件**，因此没有字体授权问题；
  若后续要内嵌，请优先选择 OFL 授权字体（思源宋体 / 霞鹜文楷），并随包附上 `OFL.txt` 全文

### 字号（对应 HIG Typography）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--t-large-title` | 34px | 页面主标题 |
| `--t-title1` / `--t-title2` | 28 / 22px | 区块大标题 |
| `--t-title3` | 20px | 卡片标题 |
| `--t-headline` | 17px | 强调正文（半粗） |
| `--t-body` | 15px | 正文 |
| `--t-callout` | 14px | 按钮、控件 |
| `--t-subhead` | 13px | 辅助说明 |
| `--t-footnote` | 12px | 元信息 |
| `--t-caption` | 11px | 角标、最次要信息 |

### 中文排版的三条硬规则

1. **`letter-spacing: 0`。** 汉字本身就是 1:1 的正方形，加任何字距都会破坏这个网格
   （依据 [W3C clreq](https://www.w3.org/TR/clreq/)）。负字距只用于西文与数字。
2. **行高比西文更高。** 中文正文 `1.72–1.8`，标题 `1.3`；西文习惯的 1.5 会让中文显得挤。
3. **测度用 `em` 而不是 `ch`。** `65ch` 是拉丁文启发式，汉字字面约为拉丁小写的两倍宽，
   用 `ch` 会得到远超预期的行宽。本项目用 `max-width: 34em`（约 34 个汉字一行）。

## 四、间距、圆角与材料

### 关于 8pt 网格：一处需要更正的归属

**Apple HIG 并没有「8pt 网格」这条规定。** 通读 `/layout` 全文（中英文版）后确认：没有任何 `8 点 / 8pt / 网格间距 / base unit` 之类的表述；`/spacing` 页面在 2022 年那次重构后**已不存在（404）**。HIG 的「规范」小节只列了三类表：iOS/iPadOS 设备屏幕尺寸、设备尺寸分类、watchOS 设备屏幕尺寸 —— 全是屏幕尺寸，不是间距体系。

8pt 网格是 Apple 平台**事实上的工程惯例**（来自 AppKit/UIKit 的度量与设计资源模板），但不是 HIG 明文规范。本项目用 4px 基数递增是工程选择，不宣称是 Apple 的规定。

**HIG 里真正存在的间距数值（已核验原文）**：

| 数值 | 出处 |
|---|---|
| 约 12pt | 「在包含外框的元素四周添加约 12 点的内边距效果很好」 |
| 约 24pt | 「对于没有外框的元素，在元素的可见边缘四周添加约 24 点的内边距效果也很好」 |
| ≥ 44×44pt | 「按钮需要至少 44x44 点的点击区域」（macOS 控制本身 28×28，最小 20×20） |
| 1pt | 「细分隔线宽度为 1 点」（macOS 拆分视图面板分隔线） |
| < 15 字符 | 窗口标题长度上限 |
| ≤ 3 组 | 工具栏分区数量上限 |

### 圆角与连续曲率

**`-electron-corner-smoothing`** 是 Electron 独占的 CSS 规则，官方说明它「非常接近 Apple 在 SwiftUI 里的连续圆角（squircle）」。关键细节：`system-ui` 关键字在 macOS 上是 **60%**、在 **Windows/Linux 上被解析为 0%**（即普通圆角）。所以必须显式写 `60%`，Windows 上才拿得到那种曲率。它同时会改变 `border` / `outline` / `box-shadow` 的形状。

**同心圆角规则**（Apple WWDC25 原文：*"concentric shapes calculate their radius by subtracting padding from the parent's"*）：

```css
--r-window: 26px; --pad: 8px; --r-inner: calc(var(--r-window) - var(--pad));
```

档位：窗口 26px、卡片 20px、面板 26px、主视觉 34px。
**唯一例外是拍立得相纸用 3px** —— 真实相纸几乎是直角，圆角一大就变成「卡片 App」。

### 材料与纵深

- 标题栏与左侧栏：`backdrop-filter: blur() saturate()`
- 卡片与面板：分层阴影 + 一道内高光
- **`backdrop-filter` 全应用只在模态遮罩用一次强模糊**
- **玻璃元素上不要叠 `mix-blend-mode` 的光晕**：MDN 明确说 `mix-blend-mode` 不是 `normal` 的元素会成为 backdrop root，会把它自己的 `backdrop-filter` 截断。所以跟手光晕只给按钮这类小控件，玻璃面板只保留静态的四层光影（这一条在实现中真实踩到过）

### 分隔线：官方答案不是画线

Apple 在 WWDC25 讲 scroll edge effect 时的原话是 **"replacing hard dividers with subtle blur"**，并强调「它不是装饰，不遮挡也不压暗，只是说明 UI 与内容在哪里交界」。

所以侧栏右边界与标题栏下边界都是**两端淡出的模糊带 + 一道极淡的渐隐发丝线**。真需要线时按 HIG 用 **1pt 细分隔线**。

### 分层阴影

每一档都是三段叠加，色相统一（暖纸模式用暖棕，空间模式用纯黑）：

```css
/* 接触层（最小最锐，最不透明） + 关键层（决定光从哪来） + 环境层（最淡最大） */
--shadow-print:
  0 1px 1px        rgba(53,40,28,.12),
  0 6px 14px -4px  rgba(53,40,28,.16),
  0 26px 48px -18px rgba(53,40,28,.30);
```

## 四之二、三套外观

| 外观 | 底色 | 材质 | 气质 |
|---|---|---|---|
| **浅色 · 暖纸**（默认） | `#f6efe6` 未漂白棉纸 | 半透明暖纸 + 分层暖棕阴影 | 纸感、仪式、慢 |
| **深色 · 暗房** | `#171310` 暗房暖褐 | 暖褐玻璃 + 琥珀光 | 夜里的一盏灯 |
| **空间 · 玻璃** | `#050505` 近黑 | 毛玻璃 + 冷色光雾 + 系统语义色状态点 | 未来、克制、信息密度高 |

**空间外观的构成**（`renderer/css/spatial.css`）：

1. **近黑底 + 冷色光雾**：不用真实模糊照片（费性能且不可控），改用四团极低透明度的冷色径向渐变（蓝 / 紫 / 青 / 白）
2. **毛玻璃面板**：`rgba(255,255,255,0.045)` 填充 + `blur(28px) saturate(1.3)` + `rgba(255,255,255,0.08)` 描边 + `inset 0 1px 0 rgba(255,255,255,0.1)` 顶部镜面高光
3. **文字三级**：90% / 62% / 50% / 32% 白
4. **唯一的色彩出口是状态点**：`#FF453A` 红 / `#0A84FF` 蓝 / `#32D74B` 绿 / `#BF5AF2` 紫
5. **排版**：标题用无衬线细体（300）+ 白→60%白的**竖向渐变文字裁切**；微标签用等宽字体 + `0.2em` 字距 + 大写
6. **缓慢浮动**：侧栏与右栏 8.5–9.5s 一个来回、幅度仅 4px（是「材质在轻轻浮动」，不是「面板在动」），`reduce-motion` 时完全停掉
7. **相纸换成冷调**：内容仍是相纸，但用 `#d7dade → #c3c8ce` 的冷灰，环里的再压深一档，避免在近黑底上跳出来

**切换位置**：设置 → 外观 → 明暗模式。

## 四之三、第四种底色：照片底图

三套外观都是「底色自己发光」（暖纸 / 暗房 / 近黑 + 冷雾）。照片底图是第四种，
也是最难的一种：**底色不再由我们决定**。用户可能传一张很暗的夜景，也可能传一张
中间有一条太阳带的黄昏 —— 后者会把玻璃面板照成暖橙色，压在上面的白字当场失去背衬。

所以照片模式下有四条硬规则，全部由 `[data-bg="photo"]` 这一个开关驱动
（不设底图时该属性被删除，三套外观一点不动）：

1. **文字全部转白，表面转暗玻璃。** 深褐文字压深色照片 = 一片糊；
   米白面板压深色照片 = 一块死白。白色薄纱尤其错：白纱叠亮底图等于面板跟着亮，
   白字失去背衬。暗玻璃则不管底图多亮，面板都稳定落在「比背景暗」的位置 ——
   这正是 macOS 与 iOS 在照片上做 vibrancy 的做法。

2. **亮度自适应。** 压暗层（0.20 → 0.48）、面板本体、强调色文字三处都跟着底图
   平均亮度走。固定值只能对一类照片成立。

3. **强调色必须拆成两个令牌。** `--theme` 是**填充**：主按钮背景是它的渐变，
   上面压着近白文字，天生偏暗。`--theme-text` 是**文字与描边**，压在玻璃上，
   背景多亮它就得跟着亮。默认两者同值；照片模式下只提亮后者，色相不变。

4. **相纸是唯一的例外，必须始终实心暖白。** 相纸在模拟实体纸张，
   透出底图会毁掉这个隐喻 —— 深色底图上尤其重要，否则相纸会和背景糊在一起。

**三套外观在照片模式下仍然要能分辨。** 否则用户切了「外观」却看不出变化，
等于把三套里的一套吃掉了。所以按 `data-mode` 给出不同的玻璃厚度：
浅色最薄（看得见照片）、暗房最厚（照片退到很远）、空间偏冷且描边带蓝。

**调试这一类问题不要靠眼睛。** 一屏有几十处文字，在缩略图里根本数不清哪些对比度不够。
`dev/shot.js --audit` 会把所有可见文字按计算颜色分组打出来，
`--probe` 打印解析后的令牌值与关键元素的实算背景，`--bare` 单独看背景层本身。

## 五、动效

### 时长分级

| 令牌 | 值 | 用途 |
|---|---|---|
| `--d-instant` | 120ms | 按下反馈 |
| `--d-fast` | 180ms | hover 变色、位移 |
| `--d-base` | 260ms | 常规过渡 |
| `--d-slow` | 380ms | 面板展开 |
| `--d-slower` | 560ms | 视图切换 |
| `--d-cinematic` | 1100ms | 叙事动效 |
| `--d-develop` | **2400ms** | 拍立得冲印（叙事动效） |

**界面动效预算：120 / 180 / 260 / 380 / 560ms，一律不超过 560ms。**
只有三处**叙事动效**刻意放慢，并且写在注释里说明这是产品气质而非拖沓：
**显影 2400ms · 抽卡翻面 1050ms · 交卷庆祝 1100ms**。

### 缓动曲线

| 令牌 | 值 | 用途 |
|---|---|---|
| `--e-out` | `cubic-bezier(.23,1,.32,1)` | 到达型（进入、展开）——强 ease-out，比 CSS 内置曲线更干脆 |
| `--e-in-out` | `cubic-bezier(.77,0,.175,1)` | 屏幕位移型（翻牌） |
| `--e-overshoot` | `cubic-bezier(.34,1.56,.64,1)` | 小元素的轻微过冲（日历点亮、徽章） |
| `--e-settle` | `cubic-bezier(.16,1,.3,1)` | 落定（相纸弹出、视图进场） |
| `--e-anticipate` | `cubic-bezier(.6,-.28,.735,.045)` | 蓄力（洗牌前的反向动作） |

**离开比进入更快更柔**：弹层进入 620ms，离开 300ms。

### 动效清单

| 位置 | 动效 | 时长 |
|---|---|---|
| 开幕 | 整页从空白「显影」出来（blur + brightness + contrast + saturate 同动） | 1250ms |
| 环境层 | 三团暖光缓慢漂移（34s / 42s / 50s alternate）、胶片颗粒 `steps(1)` 跳变 | 循环 |
| 视图切换 | 淡入 + 上移 14px + 去模糊，外加一道斜向「冲洗」扫光 | 620 / 700ms |
| 进度环 | `stroke-dashoffset` 补间 + 数字滚动 | 1400 / 1200ms |
| 15 格网格 | 逐格浮现（错峰 42ms） | 620ms |
| 抽卡 | 洗牌（模糊 11px + 缩放 0.72）→ 发牌（错峰 110ms）→ 3D 翻卡 | 460 / 620 / 1050ms |
| **冲印显影** | blur/brightness/contrast/saturate/sepia/hue-rotate 六通道同动 + 显影液扫光 | **2400ms** |
| 相纸翻面 | `preserve-3d` + `rotateY(180deg)`，背面文字预先 `rotateY(180deg)` 抵消镜像 | 900ms |
| 相纸吐出 | 从出纸槽滑出并轻微回弹 | 1150ms |
| 提交成功 | 34 颗粒子迸发 + 相纸重新显影 | 1100ms |
| 情绪轨迹 | Canvas 手绘曲线逐段揭示（`lineDashOffset`）+ 数据点逐个出现 | 1500ms |
| 回顾文字 | 逐字浮现（手写感） | 26ms/字 |
| 相纸墙 | 错峰浮现（62ms） | 820ms |
| 今天那格 | 呼吸光环 | 2800ms 循环 |

### 无障碍

- **焦点环用双色**：墨色 `outline` + 纸色 `box-shadow` 光晕。
  纸纹背景会不断变化，单色描边在某些区块上会「消失」，双层结构保证在任何底色上都成立
- **尊重 `prefers-reduced-motion`**，并且在设置页提供应用内的独立开关
- **命中区域 ≥ 40px**（对应 HIG 的 44pt 触控标准，桌面端略收紧）
- 所有图标是内联 SVG，配 `aria-hidden`；弹层有 `role="dialog"` 与 `aria-modal`

## 六、应该避免的（反面清单）

这几样一旦出现，整个产品就会滑向「通用 dashboard」：

1. ❌ 纯黑阴影 —— 在暖纸上显脏。只用暖棕 `rgba(74,55,38,α)`
2. ❌ 大面积玻璃拟态 —— 玻璃的前提是「背景是风景」，而本产品的核心是**纸**，纸不透明
3. ❌ `transition: all` —— 会误伤布局属性导致掉帧，永远只写具体属性
4. ❌ 相纸用大圆角 —— 拍立得相纸是接近直角的
5. ❌ 把所有东西装进居中的卡片、全都居中 —— 用非对称双栏、随机倾斜、让相纸破格
6. ❌ 中文加字距、用 `ch` 量测度 —— 见第三节
7. ❌ 抽卡加光柱/音效爆点 —— 本产品靠**仪式**驱动而不是**刺激**，慢就是高级
8. ❌ 排行榜、社交比较、「超越 XX% 用户」—— 产品文档 5.4 明确禁止

- 窗口默认 1440×920，最小 1180×760；桌面端按「宽屏 + 高信息密度」而非手机版式设计
- 未做响应式手机版式，因为产品文档的 MVP 目标是微信小程序，桌面 Demo 只用于验证视觉方向
- 照片是 Canvas 程序化生成的（8 种画面 + 胶片调色 + 亮度加权颗粒），
  不追求照片级真实，只求「一眼像胶片」的质感统一
